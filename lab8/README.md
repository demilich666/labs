Многопоточный конвейер обработки данных Лабораторная работа №8

Проект реализует расширяемый конвейер для параллельной обработки данных, хранящихся в реляционной базе данных. Данные загружаются из таблицы-источника, проходят через цепочку настраиваемых процессоров и сохраняются в результирующую таблицу. Архитектура построена на сочетании кастомных аннотаций, рефлексии, функционального стиля Stream API и многопоточности.

Основной стек технологий
Java Core (аннотации, Reflection API)
Stream API (функциональные преобразования потоков данных)
Java Concurrency Utilities (ExecutorService, CompletableFuture)
JDBC (подключение к PostgreSQL, пакетная обработка)

Содержание и архитектура заданий

1. Создание кастомной аннотации @DataProcessor
Аннотация предназначена для маркировки методов-обработчиков и определения порядка их выполнения.
Доступна во время исполнения (RetentionPolicy.RUNTIME).
Цель — только методы (ElementType.METHOD).
Параметр order задаёт очерёдность процессора в конвейере; значение по умолчанию равно 0.

2. Реализация модулей-обработчиков (процессоров)
Каждый процессор — это независимый класс с единственным публичным методом, помеченным @DataProcessor.
Метод принимает и возвращает Stream<DataRecord>, что позволяет объединять обработчики в цепочку.
TrimProcessor (order = 1): удаляет начальные и конечные пробелы в значении каждой записи.
FilterBlankProcessor (order = 2): отбрасывает записи, у которых значение null или состоит только из пробелов.
UpperCaseProcessor (order = 3): приводит значение к верхнему регистру.
StatisticsProcessor (order = 4): выводит в консоль статистику по обрабатываемому чанку — количество записей и среднюю длину значения.

3. Менеджер данных DataManager
Отвечает за полный жизненный цикл данных: загрузку, обработку и сохранение.
Метод loadData выполняет SQL-запрос SELECT к указанной таблице, создаёт список объектов DataRecord.
Метод registerDataProcessor сканирует переданный объект с помощью рефлексии, находит все методы с @DataProcessor, проверяет сигнатуру и сохраняет их с сортировкой по order.
Метод processData разбивает загруженные записи на чанки, число которых зависит от количества доступных процессоров. Каждый чанк обрабатывается в отдельном потоке через ExecutorService. Внутри чанка процессоры применяются последовательно согласно order. Результаты всех чанков объединяются и сортируются по идентификатору.
Метод saveData сначала очищает таблицу назначения, затем с помощью пакетной вставки (batch) записывает все обработанные записи. null-значения пропускаются. Транзакция завершается коммитом.
Вспомогательный класс ProcessorStep хранит объект-обработчик, метод и его порядок.

4. Инициализация базы данных DatabaseInitializer
Метод init создаёт таблицы source_data и processed_data, если они ещё не существуют.
Метод seedSourceDataIfEmpty заполняет source_data тестовыми строками, если таблица пуста.

5. Конфигурация и точка входа
Класс DatabaseConfig читает параметры подключения из системных свойств (db.url, db.user, db.password) с возможностью указания значений по умолчанию.
Метод openConnection открывает соединение с базой данных через DriverManager.
В Main последовательно выполняются инициализация БД, регистрация всех процессоров, загрузка, обработка и сохранение данных.

Ключевые инструменты и методы

Аннотации и рефлексия. Аннотация @DataProcessor позволяет динамически подключать новые обработчики без модификации DataManager. Рефлексия (Method.invoke) используется для вызова методов, обнаруженных по аннотации.

Stream API. Все преобразования записей строятся как цепочки операций над Stream<DataRecord>: map для трансформации значений, filter для отбора, collect для материализации.

Многопоточность. ExecutorService создаёт пул потоков фиксированного размера. CompletableFuture.supplyAsync запускает обработку чанка асинхронно, а join дожидается результата. Такой подход позволяет параллельно обрабатывать части набора данных.

Пакетная работа с БД. Для ускорения сохранения используется addBatch и executeBatch PreparedStatement. Транзакция управляется вручную через setAutoCommit(false) и commit.

Иммутабельность. Класс DataRecord не содержит сеттеров; для обновления значения предусмотрен метод withValue, возвращающий новый экземпляр.
